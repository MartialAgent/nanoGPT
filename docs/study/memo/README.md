# 학습 로그 (memo)

[`../README.md`](../README.md)를 읽거나 코드를 파다가 **질문이 생겨 해소된 순간**을 기록하는 폴더입니다.

가이드 본문(`README.md`)이 "정리된 결과"라면, 이곳은 **"어디서 왜 막혔고 어떻게 풀렸는지"의 기록**입니다.
같은 질문을 다시 던지지 않기 위해, 그리고 뒤따라 읽는 사람이 같은 지점에서 덜 막히도록 남깁니다.

---

## 사용 규칙

1. 로그는 **`README.md`의 장 번호에 대응**하는 파일에 쌓입니다. (`05-model-py.md` ↔ 본문 5장)
2. 파일이 없으면 그때 만듭니다. 기록이 없는 장의 파일은 미리 만들어두지 않습니다.
3. 항목 ID는 폴더 전체에서 **연속 번호** (`LOG-0001`, `LOG-0002`, …). 장이 달라도 번호는 이어집니다.
4. 한 항목은 아래 골격을 따릅니다. **개념정리를 가장 먼저 씁니다.**
   "질문에 답한다"가 아니라 **그 주제 자체를 정리한다**는 관점으로 씁니다 — 무엇인지, 전체 과정에서
   어느 위치에 있는지, 관련 용어가 무엇인지를 순서대로 풀어씁니다. "결론"처럼 사용자의 원래 말을
   맞다/틀리다로 채점하는 톤이 되지 않도록 합니다.

   | 절            | 담는 것                                                              |
   | ------------- | --------------------------------------------------------------------- |
   | 개념정리      | 무엇인지 / 전체 과정에서 어느 부분인지 / 관련 용어 (**항목 맨 위**, 결론이 아니라 설명) |
   | 근거          | 저장소 안 실제 코드 위치 `file.py:line`                               |
   | 부가사항      | 헷갈리기 쉬운 지점에 대한 참고 설명 (일반적인 개념 차원의 설명으로 쓴다) |
   | 남은 질문     | 아직 검증 못 한 것 (검증되면 여기서 빼고 본문으로)                     |

   **사용자가 틀리게 말했던 원문이나 "이 표현은 틀렸다" 식의 교정 코멘트는 기록하지 않습니다.**
   질문을 그대로 인용하지 않고, 그 질문이 다루는 개념만 `개념정리`에 녹여 씁니다.

5. **추측을 사실처럼 쓰지 않습니다.** 확인 못 한 수치는 `남은 질문`으로 내립니다.
6. 로그 내용이 충분히 정리되면 본문 `README.md` 해당 절로 승격시키고, 여기엔 링크만 남깁니다.
